# Hermes Agent и эта база

Как настроить [Hermes Agent](https://github.com/NousResearch/hermes-agent) так,
чтобы он работал с базой ChromaDB Manager не «как-нибудь», а точно. Всё, что
здесь написано про Hermes, взято из его документации; всё, что про наш сервер, —
из исходников и живых замеров.

---

## 1. Что уже стоит на этой машине

Проверено 22 августа 2026:

| | |
|---|---|
| Hermes Agent | v0.20.4 (2026.8.18), `~/.local/bin/hermes` |
| конфигурация | `~/.hermes/config.yaml`, блок `mcp_servers` уже есть |
| сервер | `chromadb-manager`, запуск `chromadb-mcp` из `dist/ChromaDB Manager.app` |
| ключ в приложении | «hermes», только чтение, коллекция `base_adaptive`, результатов 100 |

То есть связь уже работает. Ниже — то, из-за чего она работает **хуже, чем
могла бы**, и что с этим делать.

---

## 2. Как Hermes обращается с MCP-сервером

Что важно знать про его поведение (из документации Hermes):

- **Инструменты подхватываются при запуске.** Hermes поднимает сервер
  подпроцессом, спрашивает список инструментов и регистрирует их под именами
  `mcp_<сервер>_<инструмент>` — у нас `mcp_chromadb-manager_search` и так далее.
  Называть их вручную не нужно, агент выбирает сам.
- **Вызовы по умолчанию последовательные.** Параллельные включаются на сервер
  целиком: `supports_parallel_tool_calls: true`.
- **Фильтр инструментов** — `tools.include` / `tools.exclude`; при обоих
  побеждает `include`.
- **Секреты живут в `~/.hermes/.env`**, а в конфигурации подставляются как
  `${env:ИМЯ}`.
- **После правки конфигурации** — `/reload-mcp` в диалоге или перезапуск.
  Список инструментов показывает `hermes mcp catalog`.
- Таймауты по умолчанию: вызов 300 с, подключение 60 с, проверка живости 180 с.

## 3. Что поправить в `~/.hermes/config.yaml`

Готовый фрагмент — [docs/hermes/chromadb-manager.yaml](hermes/chromadb-manager.yaml).
Три правки, каждая с причиной:

**`tools.resources: false`, `tools.prompts: false`.** Наш сервер объявляет
только возможность `tools`: ни ресурсов, ни промптов у него нет и в помине
(`MCPServer.capabilities`). Обёртки над ними — это два инструмента в списке,
которые всегда ответят отказом.

**`supports_parallel_tool_calls: true`.** Безопасно: ключу «hermes» не выписаны
ни запись, ни удаление, а приложение отвечает на каждое сообщение отдельной
задачей, так что перекрывающиеся вызовы не мешают друг другу. Выигрыш скромный
и его стоит назвать честно: тяжёлая часть работы идёт на главном потоке
приложения, поэтому параллельность сокращает ожидание, а не счёт.

**Ключ — в `.env`, а не в конфигурации.** Сейчас значение `CHROMADB_MCP_KEY`
лежит прямо в `config.yaml`. Перенести его — две строки, и делать это лучше
самому, своими руками:

```bash
printf 'CHROMADB_MCP_KEY=<ключ>\n' >> ~/.hermes/.env
```

после чего в `config.yaml` оставить `CHROMADB_MCP_KEY: "${env:CHROMADB_MCP_KEY}"`.

## 4. Главное: скилл, который учит агента спрашивать

Файл — [docs/hermes/chromadb-base-SKILL.md](hermes/chromadb-base-SKILL.md),
ставится в `~/.hermes/skills/research/chromadb-base/SKILL.md`.

Зачем он нужен, одним замером: на вопрос «во всех ли документах описано
резервное копирование» агент без подсказки зовёт поиск по смыслу и получает
куски **трёх файлов из тринадцати** — при любом числе результатов. Тот же
вопрос через `collect_mentions` даёт 752 совпадения в 20 файлах за 1.1 с.
Разница не в модели и не в базе, а в том, знает ли агент, каким инструментом
спрашивают охват.

В скилле: таблица «вопрос → инструмент», порядок работы, правила фильтров по
колонкам таблиц, обязательный `fields` для табличных строк (1883 знака
метаданных на строку против 94), подводные камни и три проверочных вопроса
с известными ответами.

Проверить, что скилл виден:

```bash
hermes skills list
```

## 5. Настройки ключа в приложении

Экран «Клиенты», ключ «hermes»:

| поле | значение | зачем |
|---|---|---|
| Результатов в MCP | 100 | уже стоит; потолок конвейера |
| Символов в документе | 800–1000 | для сравнения формулировок нужен кусок, а не весь документ |
| Символов в ответе | 24 000 | умолчание; с `fields` бюджет перестаёт быть узким местом |
| Коллекции | `base_adaptive` | сейчас одна |

Про коллекции стоит решить отдельно: таблицы с ценами, на которых мерялась
проекция полей, лежат в `base_adaptive_geaorge_4b`, а ключу она не открыта.
Пока не открыта — сценарий «собери все цены» на ней у агента не заработает.

## 6. Проверка

**Сервер отвечает без Hermes** (приложение должно быть запущено):

```bash
CHROMADB_MCP_KEY=<ключ> "/Users/USER/Documents/AI/claude/ChromaDBManager/dist/ChromaDB Manager.app/Contents/MacOS/chromadb-mcp" <<<'{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

Ожидается шесть читающих инструментов: `list_collections`,
`describe_collection`, `search`, `get_documents`, `get_file`,
`collect_mentions`.

**Hermes видит их:**

```bash
hermes mcp catalog
```

**Качество ответов** — три вопроса из скилла, ответы известны заранее:
коллекция видна; «резервн» — 752 совпадения в 20 файлах; тот же вопрос поиском
по смыслу — три-четыре файла. Если третий пункт даёт столько же, сколько
второй, значит агент всё-таки зовёт `collect_mentions`, и это хорошо.

---

## 7. Границы

- **Приложение должно быть запущено.** Hermes поднимает только мост; без
  приложения сокета нет, и вызов вернёт отказ, а не пустой ответ.
- **Ключу «hermes» доступно только чтение.** Инструменты записи и удаления
  ему даже не показываются.
- **Уведомлений об изменении списка инструментов сервер не шлёт.** После
  обновления приложения список у Hermes обновится при перезапуске или
  `/reload-mcp`.
