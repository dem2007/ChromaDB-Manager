# ChromaDB Manager

<br clear="left">

[English](README.md) · **Русский**

Нативное macOS-приложение (Swift + SwiftUI) для локальной базы знаний на
[ChromaDB](https://www.trychroma.com/) — без терминала и без Python. Оно ставит и
обновляет движок, разбирает и индексирует ваши документы, таблицы, сайты
и репозитории, ищет по ним с настраиваемым конвейером, меряет качество поиска
и даёт доступ к базе агентам по MCP — с ключами и правами. Векторы считает
локальная [LM Studio](https://lmstudio.ai/): документы с машины не уходят.

> **Версия 0.4.0.** Ниже описано то, что реализовано и работает. Что сознательно
> не делается и где у приложения границы — в разделе
> [Известные ограничения](#известные-ограничения).

```
папки, сайты,      разбор и        LM Studio         ChromaDB        поиск на экране,
git, таблицы  ──►  нарезка    ──►  (векторы)   ──►   (своя или  ──►  агенты по MCP,
                                                     внешняя)        клиенты через прокси
```

## Возможности

Главный принцип — **ничего молча.** Файл, который не прочитался, кусок, который
не влез в модель, строка, исчезнувшая из таблицы, — всё это попадает в отчёт
с причиной и действием, а не теряется. Ничего не удаляется из базы
автоматически: исчезнувшее с диска ждёт решения человека.

### База и сервер

- **Установка движка двумя путями.** По умолчанию — автономный Chroma CLI без
  Python: приложение показывает версию, размер и адрес официального релиза
  и скачивает только после подтверждения. Второй путь — `pip install chromadb`
  в собственное виртуальное окружение приложения; системный и Homebrew-питон не
  затрагиваются.
- **Обновление без потери данных:** счётчики коллекций → остановка сервера →
  копия базы → обновление → проверка, что база открывается и число документов
  совпадает. Отказаться от копии можно только отдельной галочкой «понимаю риск».
- **Локальная база** — просто папка: приложение само поднимает для неё сервер на
  `127.0.0.1`, порты не видны. **Внешний сервер** — профилем с адресом, тенантом,
  базой и токеном (токены — в Keychain). Без установленного движка с внешним
  сервером можно работать полностью.
- **Управление сервером:** запуск, остановка, перезапуск, вывод процесса с
  фильтром, логи каждого запуска на диске. Аварии переводятся на человеческий
  язык («порт уже занят другим процессом» вместо текста паники), занятость
  порта проверяется до запуска, сервер, оставшийся от прошлой сессии, находится
  и подхватывается.
- **Резервные копии** с проверкой места, восстановлением и меткой неполной копии;
  **сжатие базы** после массовых удалений; **удаление данных приложения**
  с перечнем путей и размеров — каталоги ваших баз не трогаются никогда.

### Коллекции

- Список с числом записей, размерностью, моделью и метрикой; коллекции, созданные
  не этим приложением, помечены «модель неизвестна». Модель к чужой коллекции
  можно привязать — со сверкой размерности.
- **Метрика задаётся явно, по умолчанию `cosine`**, и читается обратно с сервера.
  Умолчание самой ChromaDB — `l2`, а модели LM Studio нормированы под косинус.
- **Индекс HNSW с `ef_search` 500** у новых коллекций: с серверными 100 поиск
  по графу терял до половины настоящих ближайших на коротких запросах-терминах.
  Остальные параметры индекса — в блоке «для опытных».
- **Документы:** постраничный просмотр коллекции любого размера, полный текст,
  метаданные и превью вектора; правка метаданных; правка текста **всегда**
  пересчитывает вектор той же моделью.
- **Фильтры — деревом:** восемь операторов метаданных, вложенные `$and`/`$or`,
  поиск по тексту документа, переключение «дерево ↔ JSON» без потерь,
  сохранённые фильтры на коллекцию. Значения, которые сервер отклонит, названы
  до отправки.
- **Схемы метаданных:** типы, обязательные поля, умолчания, дата с числовым
  двойником для диапазонных фильтров; проверка документов на соответствие —
  отчётом, без переписывания.
- **Импорт CSV и JSON** с предпросмотром и сопоставлением колонок; **перенос
  коллекции пакетом `.chromaexport`** — потоково, с контрольной суммой,
  фильтром, векторами или без, продолжением с места обрыва.
- **Пересчёт векторов** — клоном в новую коллекцию или на месте, с обязательной
  копией, паузой, отменой и проверкой по завершении; заново нарезать можно
  с параметрами стратегии источника.
- **Инспектор здоровья:** пустые и короткие документы, разрывы нумерации кусков,
  сироты, расхождения со схемой, дубли и почти-дубли — по векторам из базы, без
  единого вызова модели. Инспектор только читает: решения принимает человек.
- **Обзор состава** — распределения по источникам, форматам, датам и длинам, —
  и **темы коллекции**: k-means по векторам и названия тем чат-моделью, списком
  с примерами, а не картинкой.
- **Корзина:** удалённые документы и коллекции можно вернуть; её предел
  настраивается, и о коллекции, которая в корзину не помещается, сказано в самом
  окне удаления.

### Источники и синхронизация

- **Три вида источника:** папка на диске, веб (страница, список адресов или обход
  сайта) и git-репозиторий.
- **Куда что пишется:** вся папка в одну коллекцию, подпапки — в свои коллекции,
  одна коллекция с путём в метаданных или своё правило по регулярному выражению.
- **Поля из пути:** `Системы/2025/Система 1/устав.docx` даёт `year = 2025`
  и `system = Система 1` — и по ним фильтруется выдача, вместо дробления на
  двадцать коллекций. Уровни называются по дереву папок с предпросмотром, поля
  меняются без пересчёта векторов.
- **Расширения — группами** (документы, таблицы, презентации, текст, код) с числом
  таких файлов в папке; **«Скопировать источник»** — для серии опытов без ручного
  повторения настроек.
- **Инкрементальная синхронизация по манифесту:** без изменений на диске —
  ни одного вызова модели; смена нарезки или модели — это тоже изменение.
  «План» показывает, что прогон сделал бы, ничего не записывая, с оценкой
  объёма и времени по измеренной скорости модели.
- **Обрыв не теряет данных.** Новые куски пишутся первыми, старые удаляются потом
  и явным списком; намерение записывается в журнал до первой записи, и прерванный
  прогон доигрывается при следующем запуске.
- **Среда не съедает данные:** источник помнит свой диск по UUID — не тот или не
  подключённый диск, и прогон не идёт; пропажа больше половины файлов
  останавливает прогон как похожая на отключённый диск; копирующийся файл не
  читается наполовину, файл iCloud без содержимого не скачивается молча.
- **Автоматика:** при запуске приложения, по расписанию и при изменениях в папке —
  в одной очереди задач с приоритетами, с глобальной паузой и индикатором
  в строке меню.
- **Веб:** пять обязательных ограничений обхода (глубина, число страниц, домен,
  пауза, объём), `robots.txt` и карта сайта, условные запросы с `ETag` —
  повторный обход почти бесплатен. Не-HTML по ссылке уходит в разбор документов.
- **Git:** список файлов даёт `git ls-files`, изменения — `git diff` от
  сохранённого коммита; переименование не стоит ни одного вектора; смена ветки
  замечается и ничего не запускает сама.
- **Диагностика:** все файлы, которые не прочитались или прочитались с оговорками,
  с причиной и действием — включить распознавание, ввести пароль, назначить
  профиль таблицы, повторить, исключить. Итог прогона группирует пропущенное
  по причинам.

### Разбор документов

**Ни одной сторонней зависимости и ни строчки Python:** всё читается системными
фреймворками и собственными разборщиками форматов.

| Формат | Как читается |
|---|---|
| `.pdf` | текстовый слой PDFKit; таблицы — по рамкам и координатам знаков; оглавление документа — структурой |
| `.docx`, `.doc`, `.odt`, `.rtf` | собственный разбор `.docx` и двоичного `.doc`: стили, нумерация списков по стандарту, таблицы, сноски и примечания |
| `.pptx` | слайды по порядку, таблицы, SmartArt, диаграммы, заметки докладчика |
| `.epub` | главы по `spine`, оглавление, DRM отличается от обфускации шрифтов |
| `.html` | заголовки становятся структурой; меню, скрипты и стили выбрасываются |
| `.pages`, `.key` | экспортом через сами Pages и Keynote, по разрешению |
| текст, Markdown, код, JSON | напрямую; кодировки UTF-8/16, cp1251, KOI8-R, CP866 |
| сканы | Vision, только если распознавание включено у источника |

- **Таблицы — таблицами.** В PDF таблица собирается по рамке, а не угадывается по
  пробелам; ячейка, разорванная страницей, — одной строкой; строки нумерованной
  позиции («Сервер, в составе: …») — одной записью с номером и названием.
  Значение объединённой ячейки стоит во всех её клетках, подпись во всю ширину —
  один раз. Печатный бланк с сеткой в сотню узких колонок пишется строками
  текста, а таблица внутри него — сеткой.
- **Сканы.** Скан внутри PDF с текстовым слоем распознаётся в родном разрешении,
  таблицы со скана собираются в таблицы, повёрнутая страница разворачивается,
  чертёж на большом листе читается плитками. Срок — на страницу: трудная
  страница пропускается одна, с номером в оговорках, а не роняет документ.
- **Знаки для поиска:** неразрывные пробелы и дефисы, мягкие переносы, символы
  шрифтов Symbol и Wingdings (маркеры списков) приводятся к обычным знакам;
  колонтитулы и оглавление не дублируют текст документа.
- **Происхождение видно в метаданных:** экстрактор и его версия, формат, источник
  структуры, страница, раздел (`heading_path`), слайд, признак таблиц и OCR.
  Новая версия экстрактора — **предложение, а не работа:** файлы, прочитанные
  прежней, перечислены на карточке источника, и до нажатия ничего не
  пересчитывается.
- **PDF под паролем** спрашивает пароль один раз и хранит его только в Keychain.

### Таблицы

У таблиц свой конвейер: плоская строка «2024-03-15 | 4820 | Москва» даёт вектор,
который не значит ничего.

- **Форматы:** `.xlsx`, `.xlsm`, `.xls`, `.ods`, `.csv`, `.tsv` и `.numbers` (через
  сам Numbers). `.xlsb` получает причину и совет пересохранить.
- **Режим на лист:** «Таблица данных» — строка становится документом, выбранные
  колонки идут в текст, остальные — в метаданные, и поиск сочетает фильтр
  `склад = Москва и цена < 100` со смыслом описания; «Документ» — лист режется
  стратегией источника, шапка повторяется в каждом куске; «Не индексировать» —
  служебные и скрытые листы. Автоопределение только предлагает и говорит почему.
- **Профили сопоставления** узнаются по заголовкам, хранятся у источника или
  у всего приложения, описывают книгу целиком (вариант на лист), назначаются
  файлу вручную и переносятся файлом. Лист, которому не подошёл ни один профиль,
  по умолчанию пишется текстом, а не пропадает.
- **Синхронизация построчная:** правка одной ячейки в листе на 20 000 строк
  пересчитывает одну строку, правка только метаданных — ни одной. Исчезнувшая
  строка ждёт решения.
- **Числа — как в книге:** без хвоста двоичной дроби, с числом знаков по формату
  ячейки, проценты и валюты — с единицей. Шапка в несколько строк собирается из
  объединений; поля файла и уровни пути — у каждой строки и куска листа.
- **Цена — до запуска:** число строк и время по измеренной скорости модели,
  пробный прогон на первых строках.

### Нарезка

- **Семь стратегий:** Fixed-size, Recursive, Document-based (заголовки, теги
  HTML, функции), Hierarchical (родитель и ребёнок в одной коллекции), Semantic,
  Adaptive (размер по плотности текста) и LLM-based (границы ставит чат-модель
  по номерам предложений, текст режется из оригинала, а не переписывается).
- **Таблицы режутся по строкам:** каждая часть — шапка и целые строки, шапка
  входит в размер куска, а строка длиннее куска делится по ячейкам с номером
  и названием позиции. `get_file` снимает повторённую шапку на стыках.
- **Кусок длиннее контекста модели дорезается**, а не обрезается моделью молча
  и не выбрасывает файл: по контексту в токенах и по пределу, замеренному пробой.
- **Контекст для вектора:** путь заголовков перед текстом куска или строка
  контекста от чат-модели — с отказом от модели, которая молчит.
- Умолчания — свои у каждой стратегии; предпросмотр нарезки на любом файле — тем же
  кодом, что синхронизация, и с настройками выбранного источника.

### Модели и векторы

- Список моделей LM Studio с типом и контекстом из её родного API, модель по
  умолчанию для новых коллекций, замер скорости.
- **Текст длиннее контекста не отправляется:** LM Studio отвечает на вход любой
  длины и молча читает только начало, поэтому длина проверяется до отправки.
- **Кэш векторов** (по умолчанию до 2 ГБ): уже посчитанный текст не считается
  второй раз. На результат не влияет, только на время.
- **Тестовый стенд:** вектор текста, сравнение моделей, близость двух текстов,
  предпросмотр разбора и нарезки файла.

### Поиск

Поиск — не один вызов `query`, а конвейер из восьми стадий в фиксированном
порядке:

| № | Стадия | Что делает |
|---|---|---|
| 1 | Кандидаты | векторный поиск и/или поиск по тексту |
| 2 | Слияние | Reciprocal Rank Fusion двух списков |
| 3 | Схлопывание | несколько попаданий из одного раздела — одним результатом |
| 4 | Разнообразие | MMR |
| 5 | Подъём к родителю | раздел целиком вместо дочернего куска |
| 6 | Контекст | соседние куски того же файла |
| 7 | Переранжирование | чат-моделью или cross-encoder |
| 8 | Усечение | до `n_results` |

- **Ни одна настройка поиска не требует пересчёта векторов** — это параметры
  запроса. **Профили поиска** именованы, привязаны к коллекции, переносятся
  файлом; «Умный поиск» выключается одним щелчком.
- **Приставка запроса для Qwen3-Embedding** включена по умолчанию у коллекций на
  этой модели: модель обучена искать с инструкцией, и без неё находит хуже.
- **Поиск сразу по нескольким коллекциям** — слиянием рангов и одним общим
  переранжированием.
- **«Как получен этот результат»:** кандидаты на входе и выходе каждой стадии, что
  и почему отброшено, сколько заняло. **История запросов** — с поиском,
  закреплением и кнопкой «в набор» для стенда оценки.

### Стенд оценки качества

Цикл «вариант → прогон → разметка → сравнение» — чтобы настройки выбирались
замером, а не на глаз. Как ставить опыт, чтобы он что-то значил, —
[docs/EVALUATION.md](docs/EVALUATION.md).

- **Набор запросов** копится из истории поиска; эталон — фрагмент текста, а не
  идентификатор куска: идентификаторы несравнимы между разными нарезками.
  У запроса — теги и фильтр, видимые при разметке.
- **Вариант** — «коллекция + профиль поиска»: два профиля на одних векторах
  сравниваются без единого пересчёта.
- **Разметка** — тремя кнопками у каждого результата, в карточке — самое
  содержательное место куска; подсказка чат-модели — по желанию, в метрики она
  не попадает.
- **Отчёт:** hit rate@k, recall@k, MRR, nDCG@k, баллы, задержки и **цена
  попадания** — сколько знаков агент читает на один полезный результат, вместе
  с присоединёнными соседями: крупные куски не выигрывают только потому, что
  они крупные. Запросы, на которых варианты разошлись, сравнение «было/стало»,
  экспорт в Markdown и JSON.

### Просмотр исходного документа

Из результата поиска, стенда или инспектора документ открывается на месте
куска: PDF — на странице, текст и Word — на абзаце, таблица — на строке под
своей шапкой. Подсветка собирается по частям куска — предложениям, пунктам,
ячейкам — и находит кусок таблицы в PDF, в том числе перешедший на следующую
страницу. Если место найдено не целиком, это сказано под просмотрщиком.

### Агенты и MCP

Агентские приложения подключаются к базе **инструментами**, а не запросами к API.
Главное отличие от прокси: агент присылает **текст**, а вектор считает
приложение моделью коллекции, — записать вектор чужой модели невозможно в
принципе.

- **Инструменты:** `list_collections`, `describe_collection` (поля с типами и
  примерами), `search` (тем же конвейером, что на экране, с фильтрами),
  `get_documents`, `get_file` (файл целиком текстом, картой разделов или
  кусками по порядку; раздел по заголовку; путь к файлу на диске),
  `collect_mentions` (все места, где встречается слово, по файлам — то, на что
  поиск по смыслу не отвечает), `add_documents`, `delete_documents`.
- **Два транспорта:** stdio через помощника `chromadb-mcp` в бандле (только этот
  Мак) и HTTP `/mcp` на порту прокси, с TLS и теми же ключами (выключено по
  умолчанию).
- **Права — те же ключи, что у прокси:** список коллекций, чтение, запись,
  удаление, лимиты частоты и объёма, потолки результатов и символов в ответе.
  Чужая коллекция отвечает «не найдена». Режим «только чтение» — для всех
  ключей разом.
- **Настройка агента одной кнопкой** — для Hermes и Bionic: приложение само
  вписывает сервер в конфигурацию агента и ставит скилл с правилами работы
  с базой, а затем проверяет подключение тестовым вызовом. Для остальных
  клиентов — готовый фрагмент конфигурации.
- Каждый вызов — в журнале доступа с параметрами; документы агента помечены
  `origin: "mcp"`, удалённые уходят в корзину.

Справочник по инструментам — [docs/MCP.md](docs/MCP.md), настройка Hermes —
[docs/HERMES.md](docs/HERMES.md).

### Доступ, ключи и безопасность

У самой ChromaDB нет ни прав по коллекциям, ни режима «только чтение», поэтому
разграничение живёт в прокси перед ней.

- **Прокси** пересылает байты как есть — официальный клиент `chromadb` работает
  через него без правок. **Трафик шифруется** сертификатом, который приложение
  выпускает само; отпечаток и файл для клиента — на экране «Безопасность».
- **Ключ не хранится нигде** — только его хеш; показывается один раз. Новый ключ
  создаётся без единого права: список коллекций, запись, суточный лимит,
  предельный размер документа, проверка размерности векторов.
- **Журнал доступа:** кто, когда, какая операция, коллекция, статус и объём —
  с фильтрами и экспортом; не удаляет сам себя.
- **Наружу открывается только прокси**, сервер базы всегда на `127.0.0.1`.
  Экран «Безопасность» показывает, что открыто, сколько ключей действует и на что
  стоит посмотреть; **экстренная остановка** одной кнопкой гасит всё и отзывает
  ключи.

### Интеграция с macOS

- **Строка меню:** ход индексации, очередь задач, пауза и быстрый поиск;
  **горячая клавиша** открывает поиск поверх любого приложения — без разрешения
  «Универсальный доступ».
- **Перетаскивание** папки или файлов на окно или значок в Dock; **«Службы»** —
  добавить выделенный текст или файлы Finder; **Shortcuts** — найти в коллекции,
  добавить текст, синхронизировать источник.
- **Уведомления** о падении сервера, отказах в доступе и итогах фоновых операций.
- **Интерфейс на русском и английском** — по языку системы или по выбору
  в настройках.

## Установка

Готовая сборка — на странице релизов: скачайте `ChromaDB-Manager-<версия>.zip`,
распакуйте и перенесите приложение в «Программы».

Пакет не нотаризован, поэтому при первом запуске macOS скажет, что не может
проверить разработчика:

- **macOS 14** — правый щелчок по приложению → «Открыть», подтвердить один раз;
- **macOS 15 и новее** — запустите приложение (система откажет), затем «Системные
  настройки → Конфиденциальность и безопасность» → «Всё равно открыть».

| Что | Нужно ли |
|---|---|
| macOS | 14 Sonoma или новее |
| ChromaDB | 1.x — приложение установит само |
| LM Studio | для векторов и поиска по смыслу; ставится отдельно, модели загружаются в ней |
| Python 3 | не нужен; только для второго пути установки движка |
| Pages, Keynote, Numbers | только для `.pages`, `.key` и `.numbers` |

## Сборка из исходников

Нужны Xcode 15 или новее (проверено на 26.6) и Swift 5.9+. Внешних зависимостей
нет.

```bash
git clone https://github.com/dem2007/ChromaDB-Manager.git && cd ChromaDB-Manager
./Scripts/build-app.sh release && open "dist/ChromaDB Manager.app"
```

Скрипт собирает `dist/ChromaDB Manager.app` с иконкой, entitlements, интентами
Shortcuts и подписью (Hardened Runtime, ad-hoc). В Xcode: `open Package.swift` →
схема `ChromaDBManager` → «My Mac».

```bash
swift test              # весь набор на записанных ответах, без ChromaDB и LM Studio
CHROMA_IT=1 swift test  # плюс живые тесты против настоящего сервера и LM Studio
```

App Sandbox выключен: приложение запускает внешние исполняемые файлы (`chroma`,
`git`, при втором пути — `python3`), что с песочницей несовместимо. Hardened
Runtime включён, entitlements — сетевой клиент и сервер (второй — для прокси).

«Службы» система регистрирует только у приложения в `/Applications`
или `~/Applications`; интенты Shortcuts собираются, только если установлен Xcode.

## Известные ограничения

- **Векторы считает приложение, а не сервер.** Поэтому за коллекцией закреплена
  модель, а какой моделью посчитаны векторы чужой коллекции, узнать невозможно —
  сверяется только размерность. То же и в прокси: внешний клиент присылает
  вектор, и «та ли это модель» проверяется только как совпадение размерности.
- **Размерность коллекции фиксируется первой записью навсегда**: пересчёт на
  месте — только на модель той же размерности, для другой — клонирование.
- **Порядок документов при листании ChromaDB не гарантирует.** Если коллекция
  меняется, пока идёт листание, страницы могут повторяться — приложение сверяет
  число и предупреждает. Порядок кусков файла гарантирует только `get_file`.
- **Сравнения `>`, `<` в фильтре — только для чисел.** Даты сравниваются через
  числовой двойник поля, который включается в схеме метаданных.
- **Подсчёт токенов приблизительный (`≈`):** токенайзер модели через API LM Studio
  недоступен; проверки длины поэтому намеренно пессимистичны.
- **Late chunking невозможен:** LM Studio отдаёт один вектор на текст, а не на
  токен.
- **Распознавание — секунды на страницу**, на большой папке сканов это часы;
  структура заголовков у распознанного текста не восстанавливается.
- **Правки в режиме рецензирования** в текст не попадают; комментарии, сноски
  и примечания — попадают.
- **Веб читается без «режима чтения»:** немного навигации на странице со сложной
  вёрсткой может попасть в текст; страницы, которые рисует скрипт в браузере,
  не поддерживаются и попадают в «требуют решения».
- **`.pages`, `.key`, `.numbers`** требуют установленных Pages, Keynote и Numbers
  и разрешения на автоматизацию; в автоматических прогонах экспорт выключен по
  умолчанию — он поднимает окно приложения.
- **Автоматика живёт, пока запущено приложение:** фоновых демонов и
  `launchd`-агентов оно не ставит.
- **Защита рассчитана на сеть, а не на других пользователей этого Мака:** порт
  базы на `127.0.0.1` доступен любому процессу машины в обход прокси.
- **Сертификат прокси самоподписанный** — доверять ему клиент должен явно, по
  файлу или отпечатку.
- **Пакет не нотаризован** — см. [Установка](#установка).

**Не будет сделано никогда:** встроенный чат с базой, управление моделями,
облачная синхронизация, многопользовательский режим, мобильный клиент,
встроенное автообновление и визуализация векторов (2D/3D-проекции, PCA, UMAP,
t-SNE) — темы коллекции показываются списком, а не картинкой.
